# Обновление и восстановление

## Перед обновлением

1. Дождитесь завершения генерации, анализа Qwen, подбора из папки и экспорта.
2. Сохраните монтаж. Поставьте Flow на паузу и дождитесь завершения уже отправленных запросов.
3. Если исход запроса Flow неизвестен, сначала найдите его результат. Обновление не является
   способом отмены запроса или разрешением отправить его ещё раз.
4. Остановите старый FrameForge штатным `StopFrameForge.ps1` или Ctrl+C в его консоли.
   Не закрывайте процесс посередине записи файла. Скрипт остановки не убивает процессы по портам.
5. Скачайте новый Windows ZIP, сравните SHA256 с опубликованным `SHA256SUMS.txt`:

```powershell
Get-FileHash -Algorithm SHA256 "D:\Downloads\FrameForge-0.2.0rc2-windows-x64.zip"
```

SHA256 обнаруживает повреждение/подмену относительно доверенной опубликованной суммы,
но не заменяет цифровую подпись издателя. EXE этого кандидата не подписан.

## Подготовить новую папку

1. Распакуйте архив целиком рядом со старой версией, например `D:\FrameForge-0.2.0rc2`.
   Не распаковывайте поверх старой программы или внутрь её data.
2. Откройте PowerShell в новой папке и выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Prepare-Update.ps1 -PreviousInstallation "D:\FrameForge-old"
```

Если данные раньше были вынесены отдельно, добавьте `-PreviousData "D:\FrameForgeData"`.

3. Скрипт проверяет `SHA256SUMS.json`, блокировку старого data и свободное место;
   копирует весь data в соседнюю `FrameForge-backups\ДАТА\data` и сверяет содержимое SHA256.
   При ошибке новая версия не подключается; неполную резервную копию не используйте для отката.
4. В новой папке создаётся только `.frameforge-profile.json` с путями данных, компонентов,
   прежнего `.env` и резервной копии. Ключи в этот файл не переносятся.
5. Запустите `Start.cmd` новой версии. База открывается существующим кодом миграций FrameForge.
   Одновременный запуск двух версий с одним data блокируется.

Старая папка сохраняется и остаётся местом хранения общих backends/models и прежнего `.env`.
Не удаляйте её после обновления. Перенос компонентов в отдельный постоянный каталог — отдельная
операция с проверкой путей. Скрипт её автоматически не выполняет.

## После запуска

- Откройте существующий проект: количество сцен, персонажей и длительность монтажа должны совпасть.
- Проверьте озвучку и 1–2 фото/видео, переключение «Показать исходный кадр».
- В Tampermonkey обновите существующий **FrameForge Flow Bridge (new)** до 0.1.83:
  `http://127.0.0.1:8765/frameforge-flow-v1.user.js`.
- Обновите вкладку Flow и инструмент адаптера, выполните «Проверить мост».
- Не устанавливайте вторую копию userscript, не удаляйте его сохранённое состояние и не нажимайте
  «Сброс кэша» для неизвестных запросов. Версии компонентов сверяются по `release.json`.
- Для Pixabay повторите сохранённый поиск: кэш за 24 часа должен использоваться повторно.

Ключ Pixabay зашифрован Windows DPAPI и рассчитан на того же пользователя Windows.
При переносе на другой компьютер/аккаунт пользователь вводит свой ключ заново.

## Откат

Новая версия может изменить схему базы. Нельзя просто открыть изменённую базу старым кодом
и считать такой откат безопасным.

1. Остановите новую версию после завершения задач.
2. Сохраните **ещё одну копию текущего data**, чтобы не потерять изменения после обновления.
3. Из проверенной предобновленческой резервной копии восстановите data в **отдельную папку**.
4. Запустите старую версию с этой копией через `Launch.ps1 -DataPath "D:\RestoredFrameForgeData"`.
5. Сверьте проекты и монтаж. Новые изменения автоматически не сливаются со старой базой.

Автоматический откат базы не реализован. Старый и новый data не перезаписываются скриптом
обновления. Резервные копии содержат личные материалы и ключи: не прикладывайте их к Release.
