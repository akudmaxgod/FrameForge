# Новый мост ФФ ↔ Flow v0.1

Это новая реализация, не основанная на скрипте 5.2.

## Создано
- `frameforge-flow.user.js`: Tampermonkey на верхней странице Flow; GM-запросы к ФФ, очередь персонажи → локации → сцены, сохранение результата перед upload, пауза после текущего задания.
- `FrameForgeBridge.tsx`: локальный образец адаптера. Реальный компонент добавлен через конструктор Flow в инструмент 40d1f327-c6e2-4e2a-b91d-a6f7875facff и отличается оформлением. Протокол проверен чтением его исходника.
- Серверная копия: `imagegen/static/frameforge-flow-v1.user.js`.
- `tests/flow_v1.spec.mjs`: 3 проверки протокола, паузы и блокировки повторной неподтверждённой генерации.

## Установка и проверка
Открыть http://127.0.0.1:8765/frameforge-flow-v1.user.js в Chrome с Tampermonkey. Старый скрипт не должен работать одновременно с новым. После установки перезагрузить вкладку инструмента и открыть предварительный просмотр. Нажать «Проверить связь»: успешный результат должен подтвердить pong от iframe и GET текущего проекта ФФ. Это не расходует генерацию.

## Подтверждено 23.09.2026
Компонент FrameForge Bridge v1 появился в реальном инструменте Flow. Локальные тесты проходят. Установка нового userscript инициирована, но окно расширения не доступно через подключённый браузерный интерфейс; установка и живая связь пока НЕ подтверждены. Генерация не запускалась.

## Ещё необходимо
- Проверить handshake в настоящем Tampermonkey (источник сообщения из sandbox может отличаться от URL iframe).
- Выполнить один полный проход генерации и сохранения в тестовом проекте.
- Поддержать импорт уже закреплённых референсов из ФФ в Flow: сейчас mediaId известны только для результатов нового моста; при неизвестном mediaId сцена останавливается.
- Перенести журнал заданий и mediaId в серверную БД и добавить идемпотентность upload. Сейчас очередь хранится в GM, неподтверждённые задания блокируются, а повтор upload после потерянного HTTP-ответа может создать дополнительную запись.
- Добавить восстановление позднего результата, обработку ошибок с явным retry/reset и независимые очереди проектов. Неопределённая генерация сейчас намеренно блокирует продолжение.
- Учесть формат проекта (сейчас портрет 1:1, остальное 16:9), изменения промптов и устаревание готовых заданий.
- Запуск из ФФ, полноценный статус, синхронизация карточек внутри инструмента, блокировка нескольких вкладок и тест всей раскадровки.

Не считать v0.1 готовой полностью автоматической интеграцией.

## Живая проверка (обновление)
Пользователь установил новый userscript в Tampermonkey. После перезагрузки вкладки проверка ping/pong и чтение `/api/projects/current` успешно завершились. В проекте `9e8b1bee-5e05-4bf0-8c19-a3080269bc0f` через новый мост сгенерированы и автоматически сохранены/зафиксированы портрет Emma (`bd6797e7-fbd2-4e61-8dcd-de0ed153e950`) и квартира (`8cee76b5-8d41-497e-98d9-a669704eade9`). Первая пауза после портрета проверена; продолжение не повторило портрет. Запущена очередь из 8 сцен с двумя референсами.

В локальном скрипте исправлено перетирание статуса повторными ready-сообщениями; установленная версия пока до этого косметического исправления. Поэтому итоговый текст статуса может замениться на «Инструмент подключён»; результат проверять по данным ФФ.

### Текущий итог живого прогона
Подтверждено API: 1 портрет, 1 локация, 6 из 8 сцен; 8 уникальных хешей изображений. На сценах 7–8 очередь остановилась, причина пока не установлена: ready-пакеты в установленной v0.1.0 перезаписывают ошибку. Подготовлена v0.1.1 с постоянным сообщением ошибки, открыт установщик обновления и ожидается действие пользователя в недоступном агенту окне Tampermonkey. После обновления перезагрузить вкладку и прочитать причину; не сбрасывать сохранённое задание и не повторять генерацию вслепую. 4 теста новой реализации проходят.

### Причина остановки установлена
После установки v0.1.1 получена ошибка ФФ: «Это изображение дублирует референс локации Emma's apartment». Это ветка приблизительного сравнения средней разницы пикселей <10, а не совпадение хеша. В `imagegen/service.py` приблизительная блокировка заменена сравнением точных нормализованных пикселей; проверки хешей сохранены. Добавлен регрессионный тест сцены с небольшим изменением на фоне той же локации. Все 117 Python-тестов и 4 JS-теста прошли.

Седьмой результат сохранён в GM state.result и может быть отправлен повторно без генерации. Нужен перезапуск Python-сервера для загрузки исправления. Попытка остановить PID 21200 (слушает 127.0.0.1:8765) отклонена Windows: Access denied. Пользователю предложено перезапустить ФФ привычным способом. После перезапуска нажать «ФФ: старт / продолжить»: сперва загрузится сохранённый кадр 7, затем должна сгенерироваться сцена 8. Не удалять состояние Tampermonkey.

### Обновление v0.1.2
Очередь теперь разделена по паре ID проекта ФФ и ID проекта Flow. Старое состояние v0.1.1 остаётся в прежнем GM-ключе и при возвращении к соответствующей паре подхватывается без сброса незагруженного результата. Новый текущий проект больше не блокируется сообщением «Сохранена очередь другого проекта». Пять JS-тестов проходят, в том числе проверка сохранения старого результата при запуске нового проекта. Установка обновления инициирована; пользователь должен нажать «Обновить» в окне Tampermonkey.

### Сквозной прогон v0.1.2 (23.09.2026)
Пользователь обновил Tampermonkey. После перезагрузки вкладки в проекте Flow `d72dddb5-c45a-4375-8026-d3e5db47d807` проверена связь с текущим проектом ФФ `673c3b26-2574-4c44-bd49-df1d479f4d3b`. Нажата кнопка «ФФ: старт / продолжить». API ФФ подтвердил: 1 персонаж зафиксирован, 1 локация зафиксирована, 8 из 8 сцен имеют изображения. Интерфейс моста показал «Очередь завершена». Причина предыдущей блокировки при переключении устранена, прежняя очередь сохранена отдельно.

### Управление из ФФ (v0.1.3)
В настройках генерации проекта ФФ при выборе Google Flow появились «Проверить мост», «Открыть Storyboard Automator Pro», «Запустить генерацию в Flow» и «Пауза после кадра». Сервер принимает heartbeat от новой версии Tampermonkey и выдаёт команды только для выбранного проекта ФФ. Кнопка открытия ведёт на инструмент Flow в отдельной вкладке; использует ID последнего подключённого проекта Flow, а до первого подключения — проверенный проект `d72dddb5-c45a-4375-8026-d3e5db47d807`.

Для живого использования нужны перезапуск ФФ после изменения серверного кода, обновление userscript до 0.1.3 и перезагрузка страницы инструмента Flow. Затем открыть проект в ФФ, нажать «Открыть Storyboard Automator Pro», дождаться статуса подключения, нажать «Проверить мост» и «Запустить генерацию в Flow». Если очередь уже завершена, новых кадров не будет. Автоматическое открытие вкладки при нажатии «Запустить» пока не предусмотрено: вкладка инструмента должна быть открыта.

Проверки: 118 Python-тестов, 5 JS-тестов моста и браузерный тест команд из интерфейса ФФ прошли. Живая проверка именно кнопок ФФ ожидает перезапуска работающего процесса на порту 8765 и обновления Tampermonkey.
